## Outcome and scope

Implement the 0.9.0 standalone research workflow with a Node-only helper and harness-owned
research. It must persist inspectable partial and final reports, validate quotes/numbers and
citations, require separately identified checker invocations, protect concurrent leases,
retain assertion identity/history, handle honest gaps, and preserve existing manual callers.
The helper never searches, extracts documents, starts agents or acquires service accounts.
The user's subsequent steering is explicit: it must remain a skill at heart. Plain-language
invocation and the model's research judgement are the product interface; bookkeeping CLI
details stay inside the skill. Live examples must actually use the skill instructions.

The 0.9.x reuse/discovery/approval/refresh/verify commands and Brand/studio migrations remain
outside this implementation. Their required identity and export foundations are included.
No publication, real-account mutation, new paid service or unrelated repository change.

## Interfaces settled for implementation

- `research start` creates a durable run; it never starts an agent. `research next` returns a
  leased task with its stage brief. `research submit`, `heartbeat` and source registration
  bind writes to the run/task/worker/attempt/token tuple. Identical accepted replays return
  acknowledgements without rewriting state. Invalid submissions record an unsuccessful
  attempt without retaining partial result mutations; obsolete leases cannot penalize a new
  owner. `research retry` explicitly reopens failed work.
- `research continue [--file PLAN]` releases a `--plan-only` hold; an edited plan is validated
  before dependent tasks exist. This fills in the spec's continuation mechanic.
- Source tasks register each selected source or an assessed access gap. Found sources require
  web authorization. Source text is registered, never fabricated or fetched by the helper.
- Check submissions attest to the original revision inspected and assess coverage/verdicts
  after confirming/narrowing/rejecting each candidate. The trusted coordinator supplies real
  invocation identities; strings are bookkeeping identities, not authentication proofs.
- The canonical run record is separate from the legacy record. Managed runs expose a legacy
  compatible projection and block unleased manual writes; manual-only runs keep their current
  semantics. Run state is authoritative after an interrupted multi-file export.
- Gap rounds are bounded by both the depth allowance and the total 80-question limit.

## Verification and review focus

Use disposable fixtures with controlled clocks to test lease expiry, fencing, concurrent
claims and idempotency. Verify original/extraction changes and stale checked facts; numeric
presence never substitutes for semantic review. Test no-fact questions and unavailable
checkers without inventing findings. Exercise repeated `status` calls and output repair
without erasing history or invalidating unchanged evidence. Preserve the distinction between
model attestations and mechanically proven checks. Do not label live acceptance complete
unless both relevant harness trials and report inspection actually ran.
